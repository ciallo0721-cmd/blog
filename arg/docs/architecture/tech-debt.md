# 技术债务清单

> 日期: 2026-03-25 | 排序: 按优先级 P0 → P3
>
> 每条债务包含: 优先级、预估工作量、影响范围、修复建议

---

## P0 — 阻塞新功能开发

### TD-P0-001: 单文件架构阻碍多人协作和功能扩展
- **优先级**: P0
- **工作量**: 4-6 小时
- **影响**: 每新增一个功能都在 720 行文件中追加代码，文件即将突破心理维护阈值
- **触发条件**: ADR-004 中定义（>800 行或 >3 个新功能同时开发）
- **修复方案**: 
  1. 按 ADR-004 方案 B 拆分为 6-7 个文件
  2. 保持 `<script>` 顺序加载，不引入模块系统
  3. 先拆分数据文件（`game-data.js`），再拆分渲染器，最后是窗口管理
- **验证**: 所有现有功能在拆分后行为不变；手动走通全部 4 个结局路径

### TD-P0-002: 缺少版本控制下的游戏状态 schema 文档
- **优先级**: P0
- **工作量**: 1 小时
- **影响**: 新功能开发者不知道 GAME_STATE 的完整字段列表和合法值，容易引入状态不一致的 bug
- **修复方案**:
  1. 在 `architecture.md` 或单独文件中创建 GAME_STATE schema
  2. 列出所有字段、类型、合法值、状态转换规则
  3. 标注哪些字段是"单次写入"（如 `endingTriggered`）、哪些是"累加"（如 `postsRevealed`）
- **验证**: schema 文档与代码中的实际使用一致

## P1 — 影响可维护性

### TD-P1-001: HTML 字符串内嵌在 JavaScript 中
- **优先级**: P1
- **工作量**: 3-4 小时
- **影响**: 修改 UI 需要在 JS 中搜索 HTML 片段；无语法高亮；难以做 UI 审查
- **修复方案**:
  1. 将静态 HTML 模板提取到 `<template>` 标签中（在 `index.html` 中）
  2. 使用 `template.content.cloneNode(true)` 替代 `innerHTML` 字符串
  3. 动态内容仍用 JS 填充，但结构从 template 获取
- **替代方案**: 将模板字符串集中到文件顶部的 `TEMPLATES` 常量对象中
- **验证**: 所有页面渲染结果与当前一致

### TD-P1-002: 终端命令 switch 需要重构为命令注册表
- **优先级**: P1
- **工作量**: 2-3 小时
- **影响**: 每添加新命令都在扩大 switch 语句；命令帮助信息与实现分离
- **修复方案**:
  ```js
  const TERMINAL_COMMANDS = {
    help: {
      desc: '显示可用命令',
      handler: () => ({ output: '可用命令：...', cls: 'terminal-output' }),
      requiresConnection: false
    },
    posts: {
      desc: '读取被隐藏的论坛帖子',
      handler: () => { ... },
      requiresConnection: true,
      sideEffects: ['postsRead']
    },
    // ...
  };
  ```
- **验证**: 所有现有命令行为不变；`help` 命令从注册表自动生成

### TD-P1-003: GAME_STATE 变更无追踪/无验证
- **优先级**: P1
- **工作量**: 2 小时
- **影响**: 难以调试状态不一致的 bug；无法实现"撤销"或"存档"功能
- **修复方案**:
  1. 创建 `setGameState(key, value)` 函数替代直接赋值
  2. 在 setter 中验证合法值
  3. 可选：记录变更日志用于调试
- **验证**: GAME_STATE 不会包含非法值（如 `browserPhase = 'invalid'`）

### TD-P1-004: 全局命名空间污染
- **优先级**: P1
- **工作量**: 1-2 小时
- **影响**: 与 `js/js/` 目录下 100+ 个 JS 文件存在冲突风险
- **修复方案**:
  ```js
  // 将所有游戏代码包裹在 IIFE 中
  (function() {
    const GAME_STATE = { ... };
    function openWindow(name) { ... }
    // 仅暴露必要的全局入口
    window.MirrorGame = { openWindow, ... };
  })();
  ```
  或使用命名空间对象将必要的全局函数放入 `window.MirrorGame`
- **验证**: HTML 中的 `onclick` 属性需要更新为 `onclick="MirrorGame.openWindow('browser')"`

### TD-P1-005: 缺失自动化测试
- **优先级**: P1
- **工作量**: 初期 4-6 小时搭建框架
- **影响**: 每次修改后需要手动回归测试所有 4 个结局路径
- **修复方案**:
  1. 使用纯 JS 测试框架（如 uvu 或裸 assert），零依赖
  2. 优先覆盖：状态转换、命令解析、结局触发条件
  3. 在文件中添加 `if (typeof module !== 'undefined') module.exports = { ... }` 导出以便测试
- **验证**: `npm test` 或浏览器中打开 `test/index.html` 运行所有测试

## P2 — 影响性能

### TD-P2-001: 终端全量重建而非增量更新
- **优先级**: P2
- **工作量**: 1-2 小时
- **影响**: 在极端使用场景下（玩家输入 200+ 条命令），性能可感知下降
- **修复方案**: 
  当 `commandHistory.length > 50` 时切换为增量追加模式：
  ```js
  // 仅追加最后一条命令
  const entry = commandHistory[commandHistory.length - 1];
  tb.insertAdjacentHTML('beforeend', `<div>...</div>`);
  ```
- **验证**: 终端响应时间在 100 条命令后 <50ms

### TD-P2-002: 无事件委托导致大量独立事件处理器
- **优先级**: P2
- **工作量**: 1 小时
- **影响**: 论坛页面中的帖子、wayback 链接等每个元素都绑定独立事件
- **修复方案**: 在父容器（`browser-content`, `terminal-body`）上使用事件委托
- **验证**: 事件处理器数量不随帖子数量增长

### TD-P2-003: CSS 动画无 `prefers-reduced-motion` 支持
- **优先级**: P2
- **工作量**: 30 分钟
- **影响**: glitch 动画对有前庭障碍的玩家不友好
- **修复方案**:
  ```css
  @media (prefers-reduced-motion: reduce) {
    .glitch { animation: none; }
  }
  ```
- **验证**: 在系统设置中开启"减少动态效果"后 glitch 动画停止

## P3 — 美好但非必要

### TD-P3-001: 添加 JSDoc 类型注释
- **优先级**: P3
- **工作量**: 2-3 小时
- **影响**: 为使用 VS Code 的开发者提供智能提示
- **修复方案**: 为 GAME_STATE、公共函数添加 JSDoc `@type` 和 `@param` 注释
- **验证**: VS Code 的 IntelliSense 正确显示类型

### TD-P3-002: 窗口系统添加 resize handle
- **优先级**: P3
- **工作量**: 2-3 小时
- **影响**: Win98 沉浸感更完整
- **修复方案**: 在窗口右下角添加 resize grip，实现拖拽调整窗口大小
- **验证**: 所有窗口可调整大小，最小尺寸限制有效

### TD-P3-003: 添加音效系统
- **优先级**: P3
- **工作量**: 4-6 小时
- **影响**: 提升恐怖氛围沉浸感
- **修复方案**: 
  1. 使用 Web Audio API 生成程序化音效（键盘敲击、glitch 音效、低频嗡鸣）
  2. 零外部音频文件依赖
- **验证**: 终端输入有键盘音效反馈；镜中人对话有扭曲音效

### TD-P3-004: 浏览器 URL 历史栈实现
- **优先级**: P3
- **工作量**: 1-2 小时
- **影响**: 启用后退/前进按钮，完善浏览器模拟
- **修复方案**: 实现简单的 `browserHistory` 栈，填充 `browserBack()` 和 `browserFwd()`
- **验证**: 在 warn → forum → wayback → snapshot 之间可前进后退

### TD-P3-005: 黑暗模式 / 更高对比度终端
- **优先级**: P3
- **工作量**: 1 小时
- **影响**: 改善可访问性
- **修复方案**: 添加 CSS 变量覆盖，或通过 `prefers-color-scheme` 支持

### TD-P3-006: 移动端响应式优化
- **优先级**: P3
- **工作量**: 3-4 小时
- **影响**: 移动端用户体验
- **修复方案**: 
  1. 移动端默认全屏单窗口模式
  2. 触摸拖拽支持
  3. 虚拟键盘弹出时调整布局
- **验证**: iOS Safari 和 Android Chrome 上的完整游戏流程
