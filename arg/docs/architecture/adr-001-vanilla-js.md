# ADR-001: 使用 Vanilla JavaScript 而非 React/Vue 框架

- **状态**: 已采纳 (Accepted)
- **日期**: 2026-03-25（文档化日期；决策最初于项目启动时做出）
- **决策者**: 项目作者
- **ADR 编号**: 001

---

## 上下文

「镜中人」是一款纯前端网页 ARG 游戏，部署于 GitHub Pages。项目需要：
- 零构建步骤（无需 webpack/vite/babel）
- 极简部署流程（`git push` 即上线）
- 小型代码体积
- Win98 复古美学，不追求现代 SPA 体验

主流选择：React、Vue、Svelte 等框架 vs 纯 JavaScript。

---

## 决定

**使用 Vanilla JavaScript (ES6+)，不使用任何前端框架。**

---

## 备选方案

### 方案 A: React / Vue（已否决）

**优点:**
- 组件化、声明式 UI
- 丰富的生态系统（状态管理、路由等）
- 虚拟 DOM 带来性能优化（在大型应用中）

**否决理由:**
- 需要构建步骤（webpack/vite），增加部署复杂度
- 框架 + 构建产物体积大（React + ReactDOM ~40KB gzipped 是游戏总代码的 4 倍）
- 为 720 行代码引入框架属于过度工程
- Win98 复古风格故意追求"不完美"体验，SPA 的流畅过渡反而不匹配
- 项目由一个开发者维护，不需要团队协作级别的组件抽象

### 方案 B: Alpine.js / htmx（已否决）

**优点:**
- 无构建步骤，通过 CDN `<script>` 引入
- 比完整框架轻量得多

**否决理由:**
- 仍然引入外部依赖，违反"零依赖"原则
- 项目的 DOM 操作复杂度低，不需要声明式绑定
- 单文件 33KB 代码量下，增加依赖的边际收益为负

### 方案 C: Vanilla JS + ES Modules（备选）

**优点:**
- 保持零依赖的同时获得模块化
- `import`/`export` 提供命名空间隔离
- 浏览器原生支持，无需打包

**当前未采纳但计划评估:**
- 使用 `<script type="module">` 需要调整现有 `<script>` 加载顺序
- 部分旧浏览器不支持（但在目标范围内可接受）
- 见 ADR-004 关于拆分单文件的讨论

---

## 后果

### 正面

1. **零依赖**: 不依赖任何 npm 包或 CDN 资源（游戏核心逻辑）
2. **零构建**: 直接编辑 `.js` 文件，保存即生效
3. **极简部署**: `git push` → GitHub Pages 自动部署
4. **体积小**: 核心游戏逻辑 ~33KB 未压缩（~10KB gzipped）
5. **可维护性**: 任何懂 JS 的人都能直接修改，无需学习框架
6. **长期稳定**: 不随框架版本升级而需要迁移

### 负面

1. **全局作用域污染**: 所有函数和变量在 `window` 下，与网站其他 JS 文件有冲突风险
2. **无组件抽象**: DOM 操作都是原始 `innerHTML` + `getElementById`
3. **手动状态管理**: 状态变更后需显式调用渲染函数，无自动重渲染
4. **代码复用困难**: 缺乏模块系统，重复代码难以提取
5. **无类型安全**: 纯 JS 无 TypeScript 类型检查

### 缓解措施

- 使用 `GAME_STATE` 作为约定前缀区分游戏状态与全局变量
- 所有游戏函数使用描述性命名（`render*`, `open*`, `trigger*`）
- 考虑引入 JSDoc 类型注释以提供 IDE 智能提示
- 按 ADR-004 的计划在代码增长时拆分文件
