## 2. 已知问题清单

### 2.1 功能缺陷 (Bug)

#### BUG-001: `browserBack()` / `browserFwd()` / `browserGo()` 是空函数
- **位置**: `arg-index.js:368-370`
- **严重性**: 低
- **描述**: 浏览器后退/前进/转到按钮被渲染为 `disabled` 或有 UI 但无逻辑
- **影响**: 用户点击"转到"按钮无反应；后退/前进按钮始终 disabled
- **建议**: 实现简单的浏览历史栈，或移除这些按钮

#### BUG-002: `minWindow()` 和 `closeWindow()` 的用户体验一致
- **位置**: `arg-index.js:68-80`
- **严重性**: 中
- **描述**: 两者都执行 `display:none`，区别仅在于 `windows[name]` 是否设为 `false`。用户无法从视觉上区分"最小化"和"关闭"
- **影响**: Win98 模拟的沉浸感受到破坏（最小化应该有动画或任务栏指示器变化）
- **建议**: 最小化时保持 `windows[name]=true`并考虑添加"已最小化"视觉标记，关闭时清除 `windows[name]=false`

#### BUG-003: `maxWindow()` 无法还原
- **位置**: `arg-index.js:82-86`
- **严重性**: 低
- **描述**: 点击最大化后窗口填满屏幕，但没有"还原"按钮或再次点击恢复原始尺寸的功能
- **影响**: 用户需要关闭再重新打开窗口才能恢复原始大小
- **建议**: 保存原始尺寸，第二次点击时恢复

#### BUG-004: 论坛回复 textarea 在重新渲染时会丢失内容
- **位置**: `arg-index.js:207-261` (renderForumPage)
- **严重性**: 低
- **描述**: 每次 `renderForumPage()` 都用 `innerHTML` 重建整个论坛页面，包括 textarea。如果用户在 textarea 中输入后再触发重新渲染（如点击回复按钮），内容可能丢失
- **影响**: 极端情况下用户输入丢失（当前实际使用中 `submitForumReply` 在渲染前读取 textarea 值，所以暂未出问题）
- **建议**: 在重新渲染前保存 textarea 值，或使用更细粒度的 DOM 更新

### 2.2 未完成功能

- **影响**: 状态机形同虚设，不能用来控制不同阶段可用的命令

### 2.3 代码质量问题

#### QUAL-001: 全局变量污染
- **描述**: 所有函数和变量都在全局作用域。`$` 函数与 jQuery 的 `$` 可能冲突（如果有其他页面使用 jQuery）；`windows`、`dragWin` 等变量名与通用词汇冲突
- **风险**: 与 `js/js/` 目录下的 100+ 个其他 JS 文件存在命名冲突可能
- **建议**: 使用 IIFE 包裹游戏代码，或用命名空间对象 `window.MirrorGame = {}`

#### QUAL-002: HTML 字符串内嵌在 JavaScript 中
- **描述**: 大量 `innerHTML = \`...\`` 调用包含完整的 HTML 模板
- **位置**: 几乎每个渲染函数（`renderWarnPage`, `renderForumPage`, `openWayback`, `searchWayback`, `openSnapshot`, `openSnapshot2003`, `renderTerminal`, `initTerminalKeydown`）
- **风险**: 
  - 难以进行语法高亮和格式化
  - HTML 与 JS 逻辑混合，修改样式可能需要在 JS 中搜索 HTML 片段
  - XSS 风险（见 SEC-001）
- **建议**: 考虑使用 `<template>` 标签或提取模板字符串到单独的常量区域

#### QUAL-003: 终端命令 switch 过于庞大
- **位置**: `arg-index.js:496-628` (~130 行)
- **描述**: `terminalKeydown` 中的 `switch(cmd)` 包含所有命令逻辑和输出文本
- **风险**: 每添加一个新命令都会增加这个 switch 的长度
- **建议**: 使用命令注册表模式（`const COMMANDS = { help: { handler, desc }, ... }`）

## 3. 性能风险点

### PERF-001: 终端全量重建
- **位置**: `arg-index.js:382-433` (`renderTerminal`)
- **描述**: 每次执行命令后，`renderTerminal()` 用 `innerHTML` 完全重建终端内容。随着 `commandHistory` 增长，重建的 HTML 字符串越来越长
- **量化**: 当前每条约 200 字符，100 条命令后约 20KB HTML。在 720 行游戏的规模下不是瓶颈
- **建议**: 当 `commandHistory.length > 50` 时，改为增量追加而非全量重建

### PERF-002: 内嵌 HTML 字符串增加 JS 文件体积
- **位置**: 所有渲染函数
- **描述**: 大量 HTML 字符串模板显著增加了 JS 文件大小（估计占 33KB 的 ~40%）
- **量化**: 纯逻辑代码约 400 行，HTML 模板约 300 行
- **建议**: 拆分文件时，将模板提取为独立变量或使用 `<template>` 标签

### PERF-003: 缺少事件委托
- **位置**: `arg-index.js:139-143` (document click 监听)
- **描述**: 开始菜单的外部点击关闭使用了 `document.addEventListener('click', ...)`，但论坛帖子点击、wayback 链接点击等都使用了内联 `onclick`
- **风险**: 每个内联 `onclick` 都是一个独立的事件处理器
- **建议**: 对动态内容使用事件委托（在父容器上监听），减少事件处理器数量

## 4. 安全隐患

### SEC-001: XSS — 用户输入直接注入 innerHTML（低风险）
- **位置**: `arg-index.js:200` (`enterForum`)
- **描述**: `GAME_STATE.playerName = name || '访客'`，但此值仅用于 URL bar 显示逻辑，未直接注入 HTML。检查确认当前无直接 XSS 向量
- **风险等级**: 低。用户名不直接出现在 `innerHTML` 中（仅用于状态追踪）
- **建议**: 如果未来在 HTML 中显示用户名，使用 `textContent` 而非 `innerHTML`

### SEC-002: 命令注入（无实际风险）
- **位置**: `arg-index.js:478-634` (`terminalKeydown`)
- **描述**: 终端命令使用严格的 `switch(cmd)` 匹配，不接受任意命令
- **风险等级**: 无。命令必须在 switch 中精确匹配才执行
- **评估**: 安全设计良好

### SEC-003: 无敏感数据暴露
- **描述**: 整个游戏在客户端运行，所有数据（帖子、结局）都是公开的叙事内容
- **风险等级**: 无
- **评估**: 纯静态 ARG，无服务端，无用户数据存储——攻击面极小

### SEC-004: 广告系统脚本的第三方风险
- **位置**: `index.html:131-132` (`ad-system.js`, `ad-data.js`)
- **描述**: 广告脚本可能引入第三方跟踪或内容
- **风险等级**: 低。广告系统为项目自有脚本，非第三方
- **建议**: 监控广告脚本对页面性能的影响

## 5. 样式健康检查

### CSS-001: 硬编码颜色值分散
- **描述**: 结局颜色和终端颜色使用 CSS 变量（`--arg-green` 等），但叙事页面颜色直接硬编码（如 `#2c3e50`, `#d4e6f1`）
- **建议**: 统一使用 CSS 变量管理颜色

### CSS-002: `transition` 和 `animation` 无性能预算控制
- **描述**: `glitch-text` 动画使用 `0.3s infinite`，对性能有轻微影响
- **风险等级**: 低。仅在特定条件下触发
- **建议**: 考虑为 glitch 效果添加 `will-change: transform` 或仅在需要时启动动画

### CSS-003: 未使用的样式
- **描述**: `.crack` 样式被定义但代码中未见使用
- **建议**: 清理或实现对应的屏幕裂纹效果

## 6. HTML 健康检查

### HTML-001: 语义化不足
- **描述**: 大量使用 `<div>` 和 `<span>`，缺少 `<main>`, `<nav>`, `<article>` 等语义标签
- **影响**: 可访问性差，SEO 无优势（但对于 ARG 游戏这可能是故意的）
- **建议**: 评估是否需要改善无障碍访问（屏幕阅读器用户）

### HTML-002: 内联样式过多
- **位置**: `index.html:17-18`, `index.html:110-118`, `index.html:126-128`
- **描述**: 广告位和 readme 内容使用内联 `style` 属性
- **建议**: 广告位的内联样式可接受（第三方广告系统），readme 内容考虑提取到 CSS
