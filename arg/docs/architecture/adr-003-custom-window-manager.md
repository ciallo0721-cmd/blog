# ADR-003: 自实现 Win98 窗口管理系统而非使用第三方库

- **状态**: 已采纳 (Accepted)
- **日期**: 2026-03-25（文档化日期；决策最初于项目启动时做出）
- **决策者**: 项目作者
- **ADR 编号**: 003

---

## 上下文

「镜中人」的 UI 是 Win98 桌面模拟，需要多个可拖拽、可最小化、可最大化的重叠窗口（浏览器、终端、readme 记事本）。需要一个窗口管理系统来管理 z-index、焦点、拖拽和窗口状态。

---

## 决定

**自实现简化的 Win98 窗口管理系统（~100 行代码），不使用任何第三方窗口/桌面库。**

---

## 备选方案

### 方案 A: 第三方桌面模拟库（如 react-rnd, WinBox, jQuery Window）（已否决）

**优点:**
- 开箱即用的窗口功能（拖拽、调整大小、最小化、最大化）
- 经过测试的边缘情况处理

**否决理由:**
- 需要引入框架依赖（如 react-rnd 需要 React，违反 ADR-001）
- WinBox 虽然纯 JS，但体积 ~10KB minified，且不匹配 Win98 视觉风格
- jQuery Window 插件需要 jQuery（~87KB），对于仅 3 个窗口严重过度
- 这些库的窗口行为是"现代"的，与 Win98 的视觉/行为约定不匹配
- 定制 Win98 风格（2px outset 边框、经典标题栏渐变、任务栏按钮状态）需要大量覆盖库的默认样式

### 方案 B: CSS-only 窗口模拟（已否决）

**优点:**
- 零 JavaScript

**否决理由:**
- 无法实现拖拽（需要 JS 事件处理）
- 无法实现 z-index 焦点管理（纯 CSS `z-index` 静态）
- 无法实现最小化到任务栏（需要 JS 状态追踪）
- 无法实现窗口内容切换（浏览器/终端/readme 需要 JS 渲染）

## 当前实现分析

当前窗口管理系统位于 `arg-index.js` 行 35-143，包含：

| 功能 | 函数 | 行数 | 评估 |
|------|------|------|------|
| 打开窗口 | `openWindow(name)` | ~14 行 | ✅ 功能完整，含默认位置 |
| 关闭窗口 | `closeWindow(name)` | ~6 行 | ⚠️ 与 `minWindow` 视觉行为相同 |
| 最小化 | `minWindow(name)` | ~5 行 | ⚠️ 仅隐藏，不清除 `windows[name]` |
| 最大化 | `maxWindow(name)` | ~4 行 | ⚠️ 无"还原"功能 |
| 聚焦 | `focusWin(name)` | ~7 行 | ✅ 正确管理 z-index |
| 拖拽 | `startDrag(e, winId)` | ~8 行 | ⚠️ 未处理窗口边界 |
| 任务栏 | `updateTaskItems()` | ~15 行 | ✅ 激活态样式正确 |
| z-index | `winZIndex` 计数器 | ~1 行 | ✅ 简单有效 |

### 已知限制

1. **无法调整窗口大小**: 窗口大小固定（无 resize handle）
2. **无法还原最大化**: `maxWindow` 后无法恢复到原始位置/尺寸
3. **最小化与关闭行为一致**: 两者都是 `display:none`，用户无法区分
4. **无窗口叠加顺序的视觉提示**: 除了 z-index 外没有阴影/亮度变化
5. **拖拽无边界限制**: 窗口可拖到屏幕外
6. **无窗口内容缓存**: 关闭再打开窗口会重新渲染（状态通过 GAME_STATE 保持）

## 后果

### 正面

1. **代码量极小**: ~100 行实现 3 个窗口的管理
2. **完全控制**: Win98 风格的视觉细节完全可控
3. **零依赖**: 不需要任何库
4. **可定制**: 添加新窗口类型只需扩展 `windows` 对象和 `openWindow` 的 switch

### 负面

1. **功能不完整**: 缺少调整大小、还原最大化、窗口边界约束
2. **边缘情况未处理**: 快速连续点击、多显示器、移动端触摸事件
3. **代码耦合**: 窗口管理与渲染逻辑混在同一文件中
4. **可复用性低**: 为「镜中人」定制的窗口管理器，难以在其他项目复用

### 缓解措施

- 窗口管理代码集中在文件的一个连续区域，有清晰的注释边界
- 功能增量添加时遵循现有模式
- 如果未来需要更复杂的窗口行为（如新窗口类型、窗口间通信），可先评估但不轻易替换

---

## 扩展建议

如果未来需要添加更多窗口类型（如文件管理器、图像查看器），建议：
1. 将窗口管理抽取为 `window-manager.js`
2. 使用窗口配置对象（`{id, title, icon, defaultPos, defaultSize, contentRenderer}`）
3. 为每种窗口类型提供 `create*Window()` 工厂函数

当前阶段（3 个固定窗口）保持现状即可。
