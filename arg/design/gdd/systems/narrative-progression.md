# SYS-04: 叙事推进系统 GDD

> **所属游戏**: 镜中人 (The Man in the Mirror)  
> **文档版本**: v1.0  
> **最后更新**: 2026-07-16  

---

## 1. 概述

控制整个游戏叙事信息的释放节奏和条件。该系统横跨浏览器和终端两个子系统，确保玩家按照设计的情感弧线（好奇→不安→恐惧→共情→选择）逐步获取信息。

### 设计目标
- 控制帖子渐进显示，防止信息过载
- 管理阶段迁移的触发条件
- 确保 Tier 2/3 内容的发现需要玩家投入
- 作为"导演"，控制叙事节奏

---

## 2. 机制

### 2.1 叙事三幕结构

```
第一幕：发现 (Act I — Discovery)
  ├── 警告页 → 论坛首页
  ├── 帖子#1-5：从技术闲聊到超自然报告
  └── 情感：好奇 → 不安
  触发：自动（阅读+回复）

第二幕：调查 (Act II — Investigation)  
  ├── 帖子#6-11：权威确认 → 关闭论坛
  ├── 时光机：2002快照 → 2003快照（可选）
  └── 情感：不安 → 恐惧
  触发：输入"时光机"关键词

第三幕：对峙 (Act III — Confrontation)
  ├── 终端连接 → 探索命令
  ├── 镜中人对话 → 最终选择
  └── 情感：恐惧 → 共情 → 选择
  触发：输入 connect 命令
```

### 2.2 信息释放节奏

```
Tier 1 (所有玩家):
  帖子#1 → #2-5 → #6-10 → #11 → 2002快照 → 终端连接 → help/posts/status/mirror → 结局A/B/C

Tier 2 (细心玩家):
  隐藏帖子#12(论坛点击) → 2003快照 → status详细角色命运 → mirror活动图表

Tier 3 (猎人):
  隐藏帖子#12(终端posts) → seal命令解锁 → 结局D → 隐藏密码（未实现）
```

### 2.3 关键推进节点

| 节点 | 触发条件 | 叙事功能 |
|------|----------|----------|
| 进入论坛 | 警告页确认 | 打破第四面墙的第一步 |
| 推进帖子 | 任意回复 | 每次推进2-3帖，保持节奏 |
| 触发时光机 | 回复含"时光机" | 奖励关键词发现，或以链接兜底 |
| 2002快照 | 点击链接 | 完整故事+终端引导 |
| 2003快照 | 点击链接(可选) | Tier 2入口 |
| 终端连接 | 输入connect | "真实"与"模拟"的界限模糊 |
| posts命令 | 终端输入 | 在终端中发现隐藏帖——不同的情境 |
| status命令 | 终端输入 | 了解角色命运——情感的转折点 |
| talk命令 | 终端输入 | 主动与未知建立联系 |

## 3. 数据

### 3.1 叙事状态快照

```javascript
// 浏览器端
browserPhase: 'warn' | 'forum' | 'wayback' | 'snapshot' | 'snapshot2003'
postsRevealed: 0-11          // 论坛中已显示的帖子索引
hiddenPostClicked: bool      // Tier 2: 点击隐藏帖子
waybackClicked: bool         // Tier 2: 访问2003快照

// 终端端
terminalConnected: bool      // 是否连接
postsRead: bool              // Tier 3: 终端中读取隐藏帖子（解锁seal）
statusChecked: bool          // Tier 2: 查看角色状态
mirrorRound: 0-4             // 镜中人对话进度

// 终局
endingTriggered: null | 'A' | 'B' | 'C' | 'D'
```

### 3.2 进度里程碑

| 里程碑 | 条件 | 完成率 |
|--------|------|--------|
| 论坛入门 | `postsRevealed >= 2` | 15% |
| 论坛中期 | `postsRevealed >= 5` | 35% |
| 论坛后期 | `postsRevealed >= 9` | 50% |
| 时光机 | `browserPhase === 'snapshot'` | 60% |
| 终端连接 | `terminalConnected` | 70% |
| 深入探索 | `statusChecked || postsRead` | 85% |
| 结局 | `endingTriggered !== null` | 100% |

## 4. 公式/规则

### 帖子推进节奏

```
BASE_POSTS_PER_REPLY = 3     // 每次回复显示3条新帖
MAX_POSTS = 11               // 总共12条帖子（索引0-11）

// 推进逻辑：
postsRevealed = min(postsRevealed + BASE_POSTS_PER_REPLY, MAX_POSTS)

// 显示逻辑：
for (i = 0; i <= postsRevealed; i++) {
  if (!FORUM_POSTS[i].hidden || hiddenPostClicked)
    render(FORUM_POSTS[i])
}
```

### 时光机引导提示

```
if (postsRevealed >= 10 && !waybackClicked):
  提示 = "论坛在2002年11月15日后关闭，但也许互联网时光机保存了更多快照……"
elif (waybackClicked):
  提示 = "你找到了2003年的隐藏快照。"
```

## 5. 边缘情况

| 场景 | 处理 |
|------|------|
| 玩家跳过论坛直接开终端 | 终端可以打开但无法连接（需要先在论坛中找到服务器地址——当前实现无强制，但叙事逻辑应如此） |
| 玩家在论坛不同阶段打开终端 | 当前无交叉影响——两个系统独立。建议：终端初始化时根据 `browserPhase` 显示不同提示 |
| 玩家多次回复相同内容 | 每次回复都触发+3（"稀释"但不会过载——有上限） |
| 时光机链接在论坛阶段早期点击 | 可以正常进入（但有叙事跳跃感——当前接受） |
| 2003快照在阅读2002快照前被点击 | 可以——两条路径独立 |

## 6. UI 接口

无独立 UI——叙事推进通过修改浏览器和终端的内容渲染来体现。

### 节奏指示器（建议新增）

可在浏览器状态栏添加隐晦的进度提示（非显式进度条）：
- 论坛阶段：帖子数标记（如 `[1/12]` 在论坛标题旁）
- 终端的镜中人活动记录中的频率增长——暗示越来越接近
