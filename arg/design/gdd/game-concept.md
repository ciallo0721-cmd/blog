## 1. 游戏标识与核心支柱

### 一句话描述

**"在模拟 Win98 桌面上翻阅 2002 年镜面论坛的遗存帖子，通过终端连接老服务器，与屏幕另一边被困的镜中人对话——你的最终选择将决定两个人的命运。"**

### 类型定位

| 维度 | 描述 |
|------|------|
| **主类型** | ARG（替代现实游戏）/ 互动叙事 |
| **子类型** | 心理恐怖、复古科技恐怖、第四面墙打破 |
| **平台** | 纯前端网页（HTML5 + CSS3 + Vanilla JS） |
| **体验时长** | 15-30 分钟（首通）；5-10 分钟（重玩） |
| **玩家数量** | 单人 |
| **核心动词** | 阅读、探索、连接、对话、选择 |

### 三大设计支柱（MDA 框架）

#### 支柱 1：复古真实感 (Retro Authenticity) — Mechanics 层

> *"这不是一个游戏——这是一台被遗忘的旧电脑。"*

- Win98 精确视觉模拟（开始菜单、任务栏、窗口 chrome、像素字体）
- IE 浏览器 + CMD 终端的双重界面
- 论坛帖子的时间戳、语言风格严格遵循 2002 年互联网文化
- 时光机存档（Internet Archive Wayback Machine 模拟）
- 终端 Telnet 连接模拟（黑底绿字 CRT 风格）

**设计原则**: 不打破 Win98 外壳——所有叙事通过"操作系统内"的界面传达

#### 支柱 2：渐进式恐惧 (Progressive Dread) — Dynamics 层

> *"一开始只是几个夜猫子的技术闲聊，然后屏幕里的倒影开始不对劲。"*

- 好奇 → 不安 → 恐惧 → 共情 → 选择 的五段情感弧线
- 信息渐进释放：从公开帖子 → 隐藏内容 → 终端探索 → 镜中人对话
- 恐惧来自认知而非 jump scare——当玩家意识到"镜中人看到你，因为你在看它"
- 第四面墙的微妙打破：镜中人的"你"既指玩家角色，也指屏幕前的真人

**设计原则**: 恐怖不来自血腥或突然惊吓，而来自"如果你凝视屏幕，屏幕也在凝视你"

#### 支柱 3：选择即叙事 (Choice As Narrative) — Aesthetics 层

> *"不是让你选'好结局'还是'坏结局'——而是让你定义自己与未知的关系。"*

- 四个结局无正邪之分，各有代价
  - A（断开）：切断通道，但永远的疑神疑鬼
  - B（接替）：承担守望者的责任与孤独
  - C（穿越）：与镜中人交换位置，体验共情的极致
  - D（封印）：忘记一切，但某种东西永远失去了
- 终端命令就是叙事选择——`sever`/`watch`/`talk`/`seal` 不只是键盘输入，是道德立场
- 隐藏结局 D 需要额外探索——"真结局"需要玩家投入

**设计原则**: 每个选择都是合理的，没有"陷阱选项"；玩家后悔的不该是选错了，而是发现每个选择都有代价

## 2. MDA 分析

### 2.1 核心动词表

| 动词 | 频率 | 系统归属 | 情感影响 |
|------|------|----------|----------|
| **阅读** | 持续 | 论坛浏览 | 沉浸、好奇 |
| **点击** | 持续 | 论坛浏览 / 时光机 | 探索 |
| **输入** | 关键节点 | 终端交互 | 主动权、紧张 |
| **等待** | 首次体验 | 终端（token-by-token 输出） | 不安 |
| **选择** | 一次（终局） | 结局触发 | 重量 |
| **连接** | 一次 | 终端 | 突破感 |
| **发现** | 稀疏 | 全局（隐藏内容） | 兴奋、成就感 |

### 2.2 情感弧线

```
好奇 ────→ 不安 ────→ 恐惧 ────→ 共情 ────→ 选择
 |           |           |           |           |
警告页     论坛帖子    隐藏帖子    终端对话    结局
  ↓           ↓           ↓           ↓           ↓
"这是什么？" "不对劲"    "真的存在"  "它也是人"  "我该怎么做？"
```

#### 各阶段详细分析

| 阶段 | 触发条件 | 玩家心理 | 设计支撑 |
|------|----------|----------|----------|
| **好奇** | 打开浏览器，看到警告页 | "这是什么？复古网站？" | 警告页制造期待；需要输入名字增加仪式感 |
| **不安** | 阅读第2-5条帖子 | "夜猫子说的是真的吗？" | 帖子从技术讨论渐变到超自然报告；时间戳在凌晨3-4点 |
| **恐惧** | 时光机存档 → 2003年最后帖子 | "它真的存在，而且还在活动" | 夜猫子最后帖子的截断文本；"它是困——" |
| **共情** | 终端连接 → 镜中人对话 | "它不是怪物，它只是被困住了" | 镜中人用三字短句、象刚学说话的人；说"冷" |
| **选择** | 输入最终命令 | "无论选什么，都有代价" | 四个命令对应四种代价；没有纯好结局 |

### 2.3 玩家类型适配（Bartle 分类法）

| Bartle 类型 | 适配度 | 吸引点 |
|-------------|--------|--------|
| **探索者 (Explorer)** | ★★★★★ | 隐藏帖子、2003快照、seal命令——大量 Tier 2/3 内容 |
| **成就者 (Achiever)** | ★★★ | 四个结局全收集；发现所有隐藏内容 |
| **社交者 (Socializer)** | ★★ | 论坛帖子模拟了社交互动，但无真多人 |
| **杀手 (Killer)** | ★ | 无竞争/PvP 要素 |

### 2.4 自我决定论 (SDT) 满足分析

| SDT 需求 | 满足方式 | 当前实现度 |
|----------|----------|-----------|
| **自主性 (Autonomy)** | 自由选择探索深度；四个结局任选 | ★★★★ 高 |
| **胜任感 (Competence)** | 发现隐藏内容；正确使用终端命令 | ★★★ 中 |
| **关联性 (Relatedness)** | 与四个角色+镜中人建立情感连接 | ★★★★ 高 |

## 3. 系统拆解

### 3.1 子系统总览

```
镜中人 ARG
├── [SYS-01] 窗口管理系统 ─────────── 基础层，所有系统依赖
├── [SYS-02] 论坛浏览系统 ─────────── 叙事入口
│   ├── 依赖：[SYS-01]
│   └── 被依赖：[SYS-04]
├── [SYS-03] 终端交互系统 ─────────── 核心玩法
│   ├── 依赖：[SYS-01]
│   └── 被依赖：[SYS-05]、[SYS-06]
├── [SYS-04] 叙事推进系统 ─────────── 控制信息释放节奏
│   ├── 依赖：[SYS-02]、[SYS-03]
│   └── 被依赖：[SYS-06]
├── [SYS-05] 镜中人对话系统 ───────── 核心叙事
│   ├── 依赖：[SYS-03]
│   └── 被依赖：[SYS-06]
└── [SYS-06] 结局触发系统 ─────────── 终局状态机
    ├── 依赖：[SYS-03]、[SYS-04]、[SYS-05]
    └── 被依赖：无（终结状态）
```

### 3.2 系统详细说明

#### SYS-01: 窗口管理系统

| 属性 | 值 |
|------|-----|
| **职责** | Win98 桌面模拟：窗口创建/关闭/最小化/最大化/拖拽、任务栏、开始菜单、时钟 |
| **当前状态** | ✅ 已实现（MVP） |
| **关键组件** | `openWindow()`, `closeWindow()`, `minWindow()`, `maxWindow()`, `focusWin()`, `updateTaskItems()` |
| **状态持有** | `windows{}` 对象追踪各窗口开关状态；`activeWin` 追踪焦点；`winZIndex` z-index 层级 |

#### SYS-02: 论坛浏览系统

| 属性 | 值 |
|------|-----|
| **职责** | IE 浏览器内渲染警告页→论坛→时光机→快照页面 |
| **当前状态** | ✅ 已实现（MVP） |
| **关键数据** | `FORUM_POSTS[]` (12条帖子，id=12为隐藏帖) |
| **状态持有** | `browserPhase`, `postsRevealed`, `hiddenPostClicked`, `waybackClicked` |

#### SYS-03: 终端交互系统

| 属性 | 值 |
|------|-----|
| **职责** | 模拟 CMD 终端：命令解析、连接认证、历史记录、输出渲染 |
| **当前状态** | ✅ 已实现（MVP含8个命令） |
| **命令表** | `help`, `posts`, `status`, `mirror`, `talk`, `sever`, `watch`, `seal`, `confirm`, `clear` |
| **状态持有** | `terminalPhase`, `terminalConnected`, `commandHistory[]` |

#### SYS-04: 叙事推进系统

| 属性 | 值 |
|------|-----|
| **职责** | 控制信息释放的节奏和条件：论坛帖子渐进显示、隐藏内容解锁条件、阶段迁移 |
| **当前状态** | ⚠️ 部分实现（嵌入在论坛/终端代码中，未独立抽象） |
| **状态持有** | `postsRevealed` (递增), `postsRead`, `statusChecked`, `mirrorRound` |

#### SYS-05: 镜中人对话系统

| 属性 | 值 |
|------|-----|
| **职责** | 管理 4 轮镜中人对话树，token-by-token 文本输出，情感节奏控制 |
| **当前状态** | ✅ 已实现（4轮→结局C） |
| **状态持有** | `mirrorRound` (0→1→2→3→4→结局C) |

#### SYS-06: 结局触发系统

| 属性 | 值 |
|------|-----|
| **职责** | 验证结局触发条件、执行结局脚本、渲染结局画面、锁定交互 |
| **当前状态** | ✅ 已实现（4结局全部可触发） |
| **结局映射** | A=`sever`, B=`watch`, C=`talk`(完成4轮), D=`seal`+`confirm`(需posts解锁) |
| **状态持有** | `endingTriggered`, `dialogLocked` |

### 3.3 数据依赖图

```
GAME_STATE (全局单例)
├── browserPhase       ← SYS-02 写入, SYS-04 读取
├── playerName         ← SYS-02 写入, SYS-06 读取
├── postsRevealed      ← SYS-02 写入, SYS-04 读取
├── hiddenPostClicked  ← SYS-02 写入, SYS-04 读取
├── waybackClicked     ← SYS-02 写入, SYS-04 读取
├── terminalPhase      ← SYS-03 写入, SYS-04/SYS-05 读取
├── terminalConnected  ← SYS-03 写入, SYS-04/SYS-05 读取
├── postsRead          ← SYS-03 写入, SYS-06 读取（D结局条件）
├── statusChecked      ← SYS-03 写入, SYS-04 读取
├── mirrorRound        ← SYS-05 写入, SYS-06 读取（C结局条件）
├── commandHistory[]   ← SYS-03 写入, SYS-03 读取（渲染）
├── endingTriggered    ← SYS-06 写入, SYS-03/SYS-01 读取（锁定）
└── dialogLocked       ← SYS-06 写入, SYS-03 读取（锁定输入）
```

### 4.2 分支条件表

| 分支节点 | 触发条件 | 结果 |
|----------|----------|------|
| 进入论坛 | 警告页输入名字 → 点继续 | `browserPhase = 'forum'` |
| 推进帖子 | 回复任意内容 | `postsRevealed += 3`（每次最多+3） |
| 进入时光机 | 回复含"时光机"/"archive"/"存档" | `browserPhase = 'wayback'` |
| 2002快照 | 点击快照链接（必须） | 看到全部11条帖子 + 终端连接提示 |
| 2003快照 | 点击第二个快照链接（可选） | `waybackClicked = true`，看到隐藏帖子#12 |
| 终端连接 | 输入 `connect mirror-forum.bbs` | `terminalConnected = true` |
| 解锁seal | 终端输入 `posts` | `postsRead = true`，解锁D结局条件 |
| 进入对话 | 终端输入 `talk` | `mirrorRound = 1` |
| 对话推进 | 镜中人对话中任意输入 | `mirrorRound++` |
| **结局A** | 终端输入 `sever`（未触发其他结局） | 断开连接结局 |
| **结局B** | 终端输入 `watch`（未触发其他结局） | 接替者结局 |
| **结局C** | `talk` → 完成4轮对话 | 穿越结局 |
| **结局D** | `posts` → `seal` → `confirm` | 封印结局（需先解锁） |

### 4.3 终局互斥验证

| 输入命令 | A | B | C | D |
|----------|---|---|---|---|
| `sever` | ✅ | ❌ (被A抢先) | ❌ | ❌ |
| `watch` | ❌ | ✅ | ❌ | ❌ |
| `talk`(第5轮) | ❌ | ❌ | ✅ | ❌ |
| `seal`+`confirm` | ❌ | ❌ | ❌ | ✅ |

> **互斥保证**: `dialogLocked` 在第一个结局触发后立即置 `true`，`endingTriggered` 非 null 时所有命令处理器直接 return。

## 6. UX 流程规格

### 6.1 全局 UX 原则

- **输入范式**: 鼠标点击（桌面/窗口 UI）+ 键盘输入（终端/论坛回复）
- **反馈原则**: 所有操作必须有即时视觉反馈（Win98 控件标准行为）
- **状态可见性**: 任务栏始终显示打开的窗口；时钟实时更新
- **错误容忍**: 终端错误命令返回友好提示而非崩溃；论坛回复不匹配关键词仍推进帖子

## 8. 跨系统一致性检查

### 8.1 状态冲突检查清单

| 检查项 | 冲突风险 | 当前状态 | 修复建议 |
|--------|----------|----------|----------|
| 浏览器 vs 终端同时打开 | 低：两个系统独立，通过 GAME_STATE 共享 | ✅ 无冲突 | — |
| 结局触发后终端仍可输入 | 高：结局触发后对话框应锁定 | ✅ `dialogLocked` 防护 | 已验证：`terminalKeydown` 中 `dialogLocked || endingTriggered` 时 return |

### 8.5 一致性修复建议（优先级排序）

1. **[P0]** 结局触发后自动关闭或禁用浏览器窗口 — 防止结局画面被遮挡
2. **[P1]** 将 `postsRevealed` 增量值（当前硬编码 `+3`）提取为配置常量 `POSTS_PER_REPLY`
3. **[P2]** 终端初始化状态：首次打开终端时考虑检测 `browserPhase` 给出情境化提示（如"你刚才在论坛看到了一些东西。也许可以试试 connect 命令。"）
4. **[P3]** 在浏览器 2003 快照中看到的隐藏帖子与终端 `posts` 中的隐藏帖子虽然内容相同，但两处发现的叙事语境不同——可在终端版本中加入额外的管理员注释
