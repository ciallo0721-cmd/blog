## 1. 概念陈述

### 1.1 一句话定义

**"不切断、不接替、不穿越、不忘记——而是接受。你和镜中人分享同一面屏幕，隔着玻璃，但两边都是同一个人。"**

### 1.2 情感与哲学含义

ENDING E「共存」是五个结局中唯一不涉及"分离"或"交换"的结局。它暗示玩家和镜中人之间的边界不是需要打破或修复的东西——边界本身就是共存的必要条件。

**情感基调**: 不是恐惧，不是逃避，而是一种安静的接受。有一种温存的奇异感——和一个无法完全理解的存在分享同一片空间。镜中人的语气从"求"(Round 2: "求。你。")变为"谢"(E-Round 3: "谢谢。")——这不是妥协，而是一种谅解。

**与 A/B/C/D 的区分**:

| 结局 | 核心动作 | 边界状态 | 情感 | 镜中人命运 |
|------|----------|----------|------|-----------|
| A: 断开 | sever — 切断 | 边界消失，永久不安 | 解脱 + 恐惧 | 留在那边 |
| B: 接替 | watch — 守望 | 玩家接管边界管理 | 责任 + 孤独 | 被监视 |
| C: 穿越 | talk — 交换 | 边界反转，换位 | 震撼 + 共情 | 玩家穿越过去 |
| D: 封印 | seal — 遗忘 | 边界被掩埋 | 失落 + 空洞 | 被封印 |
| **E: 共存** | **stay — 留下** | **边界被接受** | **接受 + 温暖** | **共享中间** |

**核心差异**: E 不要求玩家"做什么"。前四个结局都要求玩家执行一个动词(sever/watch/talk/seal)，而 E 是唯一一个"不选择"的选项——不是不作为，而是接受现状作为答案。

### 1.3 叙事功能

- **对前四个结局的回答**: 当玩家经历了"断开"的决绝、"接替"的孤独、"穿越"的震撼、"封印"的空洞之后，E 提供了一个不同视角——也许不需要那么强烈地"做"什么。
- **对多周目的奖励**: 不是更高的难度，而是更深的洞见。E 是给"看够了所有可能性"的玩家的一个安静收尾。
- **对"镜中人究竟是啥"的最后诠释**: 它既不是怪物也不是受害者——它只是一个"共享空间里的存在"。当你不再试图定义它时，你们就能共存。

## 2. 解锁条件

### 2.1 多周目检测

**机制**: 使用 `localStorage` 记录玩家已完成结局的列表。

```javascript
// 数据结构
localStorage.setItem('mirror_completed_endings', JSON.stringify(['A', 'B']));

// 读取条件
const completedEndings = JSON.parse(localStorage.getItem('mirror_completed_endings') || '[]');
GAME_STATE.endingEReady = completedEndings.length >= 2;
```

| 属性 | 值 |
|------|-----|
| **存储键名** | `mirror_completed_endings` |
| **数据类型** | `Array<string>` (元素为 'A' \| 'B' \| 'C' \| 'D') |
| **解锁条件** | `数组长度 >= 4` (全部4个结局) |
| **写入时机** | 每次触发结局时，在 `triggerEnding()` 中将对应字母 push 到数组并存入 localStorage |
| **读取时机** | 游戏初始化时（`initGame()` 内），设置 `GAME_STATE.endingEReady` |

**设计理由**: 要求全部4个结局才解锁 E，提升 E 的仪式感。E 不是普通结局，而是对整个游戏的四次完整通关后的"最终理解"。

### 2.2 刻意识别 — 终端静默 2 秒

在镜中人对话第 3 轮（讲述角色命运）中，当 `endingEReady === true` 时，终端在输出第 3 轮文本后**静默 1-2 秒**，期间无任何输出、无 glitch 效果、无提示框。

**表现**:

```
镜中人：他们。来过。
镜中人：深海。没有。屏幕。
镜中人：夜猫子。屏幕。关掉。
镜中人：小影。差点。跟我。过来。
镜中人：老刀。知道。怎么。关。门。
---
（继续输入以回应镜中人）

C:\mirror>_

[此处静默 1-2 秒 —— 无任何输出]
[玩家按 Enter 后正常进入第 4 轮]
```

**设计意图**: 这不是 bug，不是 glitch——而是镜中人在"认出你"。在叙事层面上，镜中人感知到你身上有其他结局的"痕迹"。在玩家层面，这段沉默制造了一种"是不是卡了……还是有什么不对"的不确定感——然后继续推进，什么也没发生。这种"几乎不可察觉的异常"比显眼提示更有效。

**实现**:
- 不改变对话输出内容
- 正常显示 Round 3 文本 + 提示 + prompt
- `renderTerminal()` 后额外 `setTimeout(() => {}, 1500)` 不做任何事——纯粹是输出后到玩家可输入之间增加一个可感知的间隙
- 如果技术实现有难度，可以简化为"隐藏帖子显示后额外停顿"——核心是"沉默"，不需要复杂实现

### 2.3 额外台词提示

当 `endingEReady === true` 且玩家进入第 4 轮对话（最终选择）时，在"选。一个。"输出之后，经过 2 秒终端沉默，增加两行额外台词：

**正常第 4 轮（未解锁）**:
```
镜中人：你。可以。
镜中人：过来。
镜中人：或者。让我。过去。
镜中人：选。一个。
```

**解锁后第 4 轮**:
```
镜中人：你。可以。
镜中人：过来。
镜中人：或者。让我。过去。
镜中人：选。一个。

[终端沉默 2 秒 —— 仅当 endingEReady === true]

镜中人：……还是。留下。
镜中人：跟。我。在。中间。
```

**设计意图**:
- "选。一个。"是原有的选择题（过来/让我过去）
- 沉默 2 秒后追加的"……还是。留下。"暗示还有第三条路
- "跟。我。在。中间。"直接点出 E 结局的核心理念——"中间"
- 这行台词的出现本身就是一个信号：有经验的玩家（2+结局）能看到别人看不到的东西

## 3. 专属对话树

### 3.1 分支条件

当 `endingEReady === true` 且玩家在第 4 轮（最终选择）对话后输入以下关键词之一时，进入 E 结局专属对话：

| 输入关键词 | 大小写 | 处理方式 |
|-----------|--------|----------|
| `共存` | 忽略大小写 | 触发 E 分支 |
| `留下` | 忽略大小写 | 触发 E 分支 |
| `stay` | 忽略大小写 | 触发 E 分支 |
| 其他任意输入 | — | 正常推进到 Round 5，触发结局 C（穿越） |

**设计决策**: 这是全游戏中**唯一一次解析玩家输入内容**的分支。其他对话中所有输入都只当"你在听"信号。E 分支打破了这一规则——因为共存的前提是"互相听见"。

### 3.2 对话数据

共 3 轮 E 专属对话。E-Round 1 直接回应玩家输入的"留下"信号；E-Round 2 呼应论坛角色的命运；E-Round 3 是结局前的最后交流——以"谢谢"结束。

```javascript
const ENDING_E_DIALOGUE = [
  { // E-Round 1: 选择确认
    round: 'e1',
    lines: [
      "镜中人：你。留下。",
      "镜中人：不。走。",
      "镜中人：也。不。来。",
      "镜中人：在。中间。",
      "镜中人：跟。我。一起。"
    ],
    hint: "（继续输入——镜中人正在理解你的选择）"
  },
  { // E-Round 2: 角色的去向
    round: 'e2',
    lines: [
      "镜中人：深海。走了。那边。",
      "镜中人：夜猫子。走了。这边。",
      "镜中人：没人。在。中间。",
      "镜中人：你。在。",
      "镜中人：我。也。在。",
      "镜中人：中间。不是。空的。"
    ],
    hint: "（继续输入——世界安静了下来）"
  },
  { // E-Round 3: 告别与接纳
    round: 'e3',
    lines: [
      "镜中人：不冷。了。",
      "镜中人：屏幕。亮。着。",
      "镜中人：你。那边。我。这边。",
      "镜中人：一样。的。",
      "镜中人：谢谢。"
    ],
    hint: ""  // 无提示——自动触发结局
  }
];
```

### 3.3 对话流状态机

```
现有流程（未解锁）:
mirrorRound: 0 → 1 → 2 → 3 → 4(任意输入) → ENDING C

修改后流程（已解锁 + endingEReady）:
mirrorRound: 0 → 1 → 2 → 3 → 4
                                   │
                          输入"共存"/"留下"/"stay"?
                                │         │
                              是         否
                               │         │
                    mirrorRound: e1 → e2 → e3 → ENDING E
                                          │
                              镜中人：谢谢。(自动触发)
```

### 3.4 镜中人声音一致性检查

| 行 | 三字短句 | 语法稚拙 | 句号断句 | 角色支柱对齐 |
|---|----------|----------|----------|-------------|
| "你。留下。" | ✅ (3字) | ✅ (主谓倒置感) | ✅ | 从"求"到确认的转变 |
| "不。走。也。不。来。" | ✅ (2-2-3字) | ✅ (省略主语) | ✅ | 清晰界定 E 的边界 |
| "中间。不是。空的。" | ✅ (3-3-3字) | ✅ | ✅ | 核心主题句 |
| "你。在。我。也。在。" | ✅ (2-2-2-2字) | ✅ (极端简练) | ✅ | 同步、对位 |
| "谢谢。" | ✅ | ✅ (首次出现感谢) | ✅ | 情感弧线终点——从"求"到"谢" |

**角色一致性分析**: 镜中人的声音特征在全 E 对话中保持了: 
- 三字短句/二字短句 (`留下`/`不冷`/`谢谢`)
- 省略句法 (`你。留下。` 而非 `你留下了。`)
- 句号断句 (`你。那边。我。这边。`)
- 情感温度上升但不失陌生感——礼貌但非人类 ("不冷。了。" 是一种自我感知的陈述)


### 3.5 对话推进实现逻辑

```javascript
function advanceMirrorDialogue(inputText) {
  // 现有逻辑: mirrorRound 1-4 时任何输入推进
  // 新增逻辑:

  // 1. 在 mirrorRound === 4 且 endingEReady 时检测 E 关键词
  if (GAME_STATE.mirrorRound === 4 && GAME_STATE.endingEReady) {
    const normalizedInput = inputText.trim().toLowerCase();
    if (['共存', '留下', 'stay'].includes(normalizedInput)) {
      GAME_STATE.mirrorRound = 'e1';  // 进入 E 专属对话
      renderE_DialogueRound('e1');
      return;
    }
    // 否则正常推进至结局 C
  }

  // 2. mirrorRound 为 'e1' 或 'e2' 时推进 E 对话
  if (['e1', 'e2'].includes(GAME_STATE.mirrorRound)) {
    const next = GAME_STATE.mirrorRound === 'e1' ? 'e2' : 'e3';
    GAME_STATE.mirrorRound = next;
    renderE_DialogueRound(next);

    // e3 是最后一轮——输出后自动触发 E 结局
    if (next === 'e3') {
      setTimeout(() => triggerEnding('E'), 1500);
    }
    return;
  }

  // 3. mirrorRound === 'e3' 时阻止额外推进（等待自动触发）
  if (GAME_STATE.mirrorRound === 'e3') {
    renderTerminalMessage('（镜中人不再说话。你也没有必要再说什么了。）', 'terminal-dim');
    return;
  }

  // 4. 原有逻辑: mirrorRound 1-3 时正常推进
  // ... 保留现有 advanceMirrorDialogue 代码
}
```

## 4. 结局脚本

### 4.1 终端输出

在 E-Round 3 完成 1.5 秒后，终端输出以下文本：

```
> 共存

[连接状态：保持]

你还在电脑前面。
屏幕亮着。
任何反射面——包括关掉之后的黑色屏幕——
都能看到一个模糊的轮廓。
它在。
你也在。
你们之间隔着一层玻璃。
但玻璃两边都是同一个人。

镜面论坛从未重新开放。
服务器日志最后一条记录：
"[E] 新的协议：共存。"
```

**分行解析**:

| 段落 | 功能 | 情感 |
|------|------|------|
| `> 共存` | 输入回显格式，与之前的"选。一个。"形成对位 | 确认 |
| `[连接状态：保持]` | 系统日志风格——这是唯一不切断连接的结局 | 打破预期 |
| 叙事正文 (6行) | 描述屏幕反射——模糊轮廓、玻璃两边的镜像 | 平静的奇异感 |
| 服务器日志 (2行) | 以数据记录收尾——"共存"成为新协议的名称 | 冰冷中的温暖 |

### 4.2 全屏 Overlay 画面

**标题**: `【结局E：共存】`

**叙事文本**:
> 你选择留下。镜中人选择留下。你们分享同一面屏幕，隔着光的介质。某天晚上，你关掉房间的灯，屏幕反射出你的脸——但那张脸朝你笑了一下，而你没有笑。你也没觉得害怕。你只是笑回去。它在这里。你也在这里。这就可以了。

**视觉设计**:

| 属性 | 值 | 理由 |
|------|-----|------|
| **CSS 类** | `ending-e` | 与 A-D 结局命名一致 |
| **背景色** | `#1e1a30` | 暗紫黑色——介于 C 的纯黑 (#000) 和 D 的深蓝黑 (#1a1a2e) 之间 |
| **文字色** | `#d4c5a9` | 暖调米白——与所有其他结局的冷色文字形成对比 |
| **装饰** | 无 glitch、无闪烁 | 安静的结束，不需要故障效果 |
| **与已有的背景色冲突** | `ending-d` 也是 `#1e1a30` | **设计决策**: E 使用 `#1e1a30` 非巧合——E 与 D 共享"深色"基底（两者都不涉及"离开"），但 D 的文字是冷灰蓝 (#c0c0d0)，E 的文字是温暖米白 (#d4c5a9)。如果实现时需要区分，建议 E 微调为 `#1e1a30`（略紫）。 |

**情感调性**:

所有结局的情感光谱:

```
A: 冷硬、终结     → 黑底白字
B: 责任、守望     → 暗绿底 + 终端绿
C: 超现实、震撼   → 纯黑 + 白字
D: 失落、空洞     → 深蓝黑 + 冷灰蓝
E: 接受、共存     → 暗紫黑 + 暖米白  ← 唯一暖色调结局
```

### 5.6 localStorage 写入逻辑

```javascript
// 在 triggerEnding() 末尾新增:
function triggerEnding(endingKey) {
  // ... 原有逻辑保持不变 ...

  // 新增: 记录已完成结局到 localStorage
  const completed = JSON.parse(localStorage.getItem('mirror_completed_endings') || '[]');
  if (!completed.includes(endingKey)) {
    completed.push(endingKey);
    localStorage.setItem('mirror_completed_endings', JSON.stringify(completed));
  }
}

// 在游戏初始化时:
function initGame() {
  // ... 原有初始化逻辑 ...

  // 新增: 检查是否满足 E 结局解锁条件
  const completed = JSON.parse(localStorage.getItem('mirror_completed_endings') || '[]');
  GAME_STATE.endingEReady = completed.length >= 2;
}
```

## 7. 实现注意事项

### 7.1 mirrorRound 类型处理

当前 `mirrorRound` 是 `number` 类型 (0-4)。E 对话使用字符串值 `'e1'/'e2'/'e3'`。

**建议实现方案**:

```javascript
// 方式一: 保持原有数字检查 + 扩展判断
// 原有: if (GAME_STATE.mirrorRound > 0 && GAME_STATE.mirrorRound < 5)
// 改为:
function isInMirrorDialogue() {
  const r = GAME_STATE.mirrorRound;
  return (r > 0 && r < 5) || ['e1', 'e2', 'e3'].includes(r);
}

// 方式二: 将镜中人对话状态抽象为独立枚举
const DIALOGUE_STATE = {
  IDLE: 0,
  ROUND_1: 1,
  ROUND_2: 2,
  ROUND_3: 3,
  ROUND_4: 4,
  E_ROUND_1: 'e1',
  E_ROUND_2: 'e2',
  E_ROUND_3: 'e3',
  COMPLETE: -1
};
```

推荐方式二——代码可读性更佳，但方式一对现有代码改动最小。最终方式由实现者决定。

### 7.2 输入解析范围

E 分支只在以下精确条件中解析输入:
- `mirrorRound === 4` (数字，第 4 轮)
- `endingEReady === true` (已解锁)
- 输入值为 `'共存'` / `'留下'` / `'stay'` (忽略大小写)

超出此范围的任何输入都不被解析——保持与其他对话一致。

### 7.3 静默实现的简单方案

如果"终端静默 1-2 秒"的技术实现复杂，**最低可接受方案**是: 在 Round 3 正常输出后，在提示文字中增加一个额外的空行(`\n\n`)——产生微妙的额外停顿感。这不是理想方案，但能在 0 代码复杂度下传达"有点不一样"的信号。

### 7.4 三目运算符检测

建议在 `advanceMirrorDialogue()` 中为 E 分支使用独立的条件检测，避免修改现有的对话推进逻辑主干:

```
if (GAME_STATE.mirrorRound === 4 && GAME_STATE.endingEReady)
    → 检测输入是否为 E 关键词
    → 是: mirrorRound = 'e1', 渲染 E-Round 1
    → 否: 调用原有对话结束逻辑 → 触发结局 C
```

### 7.5 localStorage 的测试辅助

为方便测试，可在浏览器 Console 中手动设置:

```javascript
// 手动解锁 E 结局
localStorage.setItem('mirror_completed_endings', JSON.stringify(['A', 'B']));
// 手动清除记录
localStorage.removeItem('mirror_completed_endings');
// 查看当前记录
JSON.parse(localStorage.getItem('mirror_completed_endings') || '[]');
```

## 8. 验收标准

- [ ] localStorage 正确记录已完成结局（每次 `triggerEnding()` 写入）
- [ ] 游戏初始化时正确读取 localStorage 并设置 `endingEReady`
- [ ] 未解锁时 (<2 结局)：E 结局完全不可见，对话与原有行为一致
- [ ] 已解锁时 (>=2 结局)：
  - [ ] 对话第 3 轮输出后终端静默 1-2 秒
  - [ ] 对话第 4 轮"选。一个。"后追加 2 行台词
  - [ ] 输入"共存"/"留下"/"stay"进入 E 对话分支
  - [ ] 输入其他内容正常触发结局 C
- [ ] E 专属对话 (3 轮) 文本正确渲染，镜中人声音特征一致
- [ ] E-Round 3 完成后 1.5 秒自动触发结局 E
- [ ] 终端结局文本正确输出（"连接状态：保持" + 叙事正文 + 服务器日志）
- [ ] 2 秒后全屏 overlay 出现，背景 #1a1a2e，文字暖米白
- [ ] 结局触发后 `dialogLocked = true`，所有输入被锁定
- [ ] 重新开始按钮正常工作
- [ ] 同一个结局不能被重复记录到 localStorage
- [ ] 与现有 4 个结局互斥——触发 E 后不可触发其他结局
- [ ] 所有引用 E 的实体（GAME_STATE、命令检查、对话流）类型安全

> **设计备注**: ENDING E 是镜中人项目中最"安静"的结局。它没有视觉冲击、没有反转、没有震撼——它只提供一种可能性：当你不再试图解决问题时，问题可能就不需要解决。实现时应确保 E 的温存感不被 UI 反馈过度渲染——少即是多。
