## 1. 音效基调陈述

### 听觉身份

> **"一台被遗忘的旧电脑，在深夜里自己亮了起来。"**

项目的听觉身份建立在 **三位一体的音景架构** 之上：

| 层次 | 描述 | 情绪目标 |
|------|------|----------|
| **CRT 底层** | 持续的、低频的电子嗡嗡声 + 荧光粉辐射噪声 | 建立"旧电脑空间"的真实感；低沉、不打扰、但始终存在 |
| **操作层** | Win98 风格的 UI 点击、窗口打开/关闭、键盘敲击 | 强化"操作系统模拟"的触感；提供即时反馈锚点 |
| **超自然层** | Modem 拨号声、glitch 静电、镜中人的低频震动、结局氛围铺垫 | 渐进式恐惧的核心载体；从微妙到显著的心理恐怖 |

### 情感曲线与音效映射

```
情感:  好奇 ─────────→ 不安 ─────────→ 恐惧 ──────────→ 共情 ────────→ 选择
音效:  桌面环境音     论坛翻页声      glitch 侵入      对话低沉震动    结局氛围铺底
       UI 交互声      打字键击声      modem 穿越       低频心跳声      (分结局差异化)
       轻微 CRT 底噪  开始菜单声      状态栏异常音      镜中人临近声    高潮 + 余韵
```

### 设计原则

1. **真实但不抢戏** — 所有音效必须 feel like 他们来自 Win98 操作系统本身，而非"游戏配乐"。玩家应该认为"这台旧电脑就是这个声音"，而不是"这个游戏有背景音乐"。
2. **恐惧来自缺失与反差** — 最恐怖的时刻不是声音最大时，而是**声音突然消失**的时刻（如结局画面切换时 CR T 嗡嗡声戛然而止）。
3. **四两拨千斤** — 本项目是纯前端网页，15-30 分钟体验。音效系统应在极小的代码/数据开销下达到最大沉浸效果。**合成优于采样。**
4. **渐进式侵略** — 前期音效几乎是不可察觉的底噪；中期开始偶尔入侵；后期出现持续性不安信号。音效不 jump scare，只在认知层面工作。

## 2. 技术选型推荐

### ★ 首选方案：Web Audio API 纯合成（零依赖，推荐实施）

**技术路线**: 使用 `AudioContext` + `OscillatorNode` + `AudioBufferSourceNode` + `BiquadFilterNode` + `GainNode` 全部由原生 Web Audio API 合成。

**推荐理由（针对本项目）**:

| 考量维度 | 评估 |
|----------|------|
| **架构一致性** | ✅ 完全符合 ADR-001"零依赖、零构建"的核心决策。不引入任何外部 JS 库 |
| **代码体积** | ✅ 音效引擎预计 ~100-150 行封装代码（约 3-4KB），零外部资产加载 |
| **审美匹配度** | ✅ 合成音效反而更适合本项目——Win98 的 CRT 嗡嗡声、modem 拨号声本身就是电子合成声。**合成音效听起来更"纯粹"、更"像记忆中的声音"，比真实录音更符合怀旧感** |
| **性能** | ✅ 所有音效实时合成，不占用网络带宽。AudioContext 是现代浏览器原生 API，零额外内存开销 |
| **控制精度** | ✅ 可精确控制音高的微妙偏移（glitch 时频率抖动）、包络（attack/release）、空间感（panning） |
| **部署** | ✅ 纯代码，无外部资产文件，git push 即上线 |

**需要注意的点**:
- Modem 拨号声需要较复杂的 oscillator 序列逻辑（~30 行代码）
- 如果未来需要真实语音（VO），Web Audio API 合成不适用，但本项目无 VO 需求
- Safari 的 AudioContext 需要在用户交互后激活（加一个"点击开始"门即可解决）

### 方案 B：Howler.js + 预录音频（备选，不推荐）

**技术路线**: Howler.js (~12KB gzip) 加载小体积 WAV/MP3 文件。

**否决理由（针对本项目）**:

| 考量维度 | 评估 |
|----------|------|
| **架构冲突** | ❌ 引入外部依赖，违反 ADR-001。增加了 CDN 引用或额外 JS 文件 |
| **体积膨胀** | ❌ 即使 Howler.js 本身 ~12KB gzip，音频文件（即使压缩）至少需要 50-200KB，总增量远超纯合成方案 |
| **部署复杂化** | ❌ 需要管理和同步音频资产文件；GitHub Pages 需要额外考虑加载延迟 |
| **审美冗余** | ❌ 真实 CRT 录音包含房间混响和背景噪音，在本项目的"纯净 Win98 沙盒"中反而失真 |
| **法律风险** | ❌ freesound.org 等素材库的 CC 许可需要署名，可能不符合项目授权要求 |

**唯一有价值的应用场景**: 如果未来需要真实乐器录音或人声（如结局 BGM 使用钢琴），此方案可作补充。

### 方案 C：Tone.js 框架（否决）

**技术路线**: Tone.js (~50KB) 基于 Web Audio API 的高级框架。

**否决理由**:

| 考量维度 | 评估 |
|----------|------|
| **体积** | ❌ ~50KB 是单文件 JS 核心（33KB）的 1.5 倍。为 5 类音效引入完整音乐框架，严重过度工程 |
| **功能过剩** | ❌ Tone.js 主要为音乐创作设计（音序器、合成键盘、效果踏板链）——本项目不需要任何音乐创作功能 |
| **架构冲突** | ❌ 外部依赖，违反 ADR-001 |
| **学习成本** | ❌ 团队需要学习 Tone.js API，而 Web Audio API 封装可以用更少的代码实现同样的效果 |

**唯一适用场景**: 如果项目未来需要 DJI（动态交互音乐）系统，根据游戏状态实时混音。但本项目只有 5 类音效，且大部分是环境音/一次性触发音，不需要音乐系统。

## 5. 技术实现规格

### 5.1 音频引擎架构

所有音效由一个轻量级封装 `AudioEngine` 对象管理（全局作用域，约 100-150 行代码）：

```
AudioEngine (全局单例)
├── .context          — AudioContext 实例 (延迟初始化)
├── .masterGain       — 主音量节点 (-6dB 默认)
├── .masterCompressor — DynamicsCompressorNode (防止峰值)
├── .bgSource         — CRT 底噪音源 (持续播放)
├── .bgGain           — 底噪音量控制 (淡入/淡出/切换)
│
├── .init()           — 创建 context + 主总线
│                      (需用户交互后调用, 遵守 auto-play policy)
│
├── .play(id, params) — 通用音效触发接口
│   参数: { loop, volume, pitch, pan, fadeIn, fadeOut }
│
├── .stop(id)         — 停止指定音效
├── .stopAll()        — 停止全部 (结局锁定用)
├── .setMasterVol(v)  — 主音量 (0-1)
├── .setBgIntensity(lv) — 设置底噪强度 (0=静音, 1=普通, 2=紧张)
│
├── 内部合成器:
│   ├── _synthCRT(options)        — SFX-01
│   ├── _synthClick(options)      — SFX-02~07
│   ├── _synthModem(options)      — SFX-08~09
│   ├── _synthGlitch(options)     — SFX-10~11
│   ├── _synthDeepDrone(options)  — SFX-12~13
│   ├── _synthScreenFlicker()     — SFX-14
│   ├── _synthEndingA()           — SFX-15
│   ├── _synthEndingB()           — SFX-16
│   ├── _synthEndingC()           — SFX-17
│   └── _synthEndingD()           — SFX-18
```

### 5.2 关键音效合成算法

#### SFX-01: CRT 底噪

```
输入: 无 (持续播放)
算法:
  1. OscillatorNode #1 — 正弦波 60Hz (增益 -18dB)
  2. OscillatorNode #2 — 正弦波 120Hz 微量 (增益 -24dB, 60Hz 谐波)
  3. AudioBufferSourceNode — 白噪声 (增益 -30dB, 轻微)
  4. BiquadFilterNode — 低通 800Hz (模拟 CRT 荧光粉辐射噪声)
  5. 三个信号混合 → 主总线
行为:
  - 游戏全程持续播放
  - bgIntensity 参数控制增益 (lvl 0: -∞, lvl 1: -18dB, lvl 2: -12dB + 增加噪声)
  - 结局时渐出或切换
```

#### SFX-05: 按钮点击 (Win98 风格)

```
输入: 无 (一次性)
算法:
  1. OscillatorNode — 方波 800Hz, 增益 -12dB
  2. GainNode — 包络: attack 1ms, decay 20ms, sustain 0
  3. 总时长 50ms
行为:
  - 频率随机微调 (±50Hz) 避免过于机械
  - 不同按钮可映射到不同频点 (确认=800Hz, 关闭=600Hz 等)
```

#### SFX-08: Modem 拨号音

```
输入: 无 (一次性)
算法:
  1. Phase 1 — DTMF 拨号音序列 (每个数字 100ms):
     [数字序列如 1-6-9-3-5-...] 由双音多频合成
     每个数字 = 两个正弦波叠加 (低频组 + 高频组)
  2. Phase 2 — 载波扫描:
     OscillatorNode 频率从 1200Hz 上升到 2400Hz, 持续 1s
     添加轻微频率调制 (颤音感)
  3. Phase 3 — 握手噪声:
     白噪声 + 带通滤波器 (1200-2400Hz) + 振幅调制
     持续 1-3s, 随机变化
  4. 总时长: 3-8s (Phase 1+2 固定 ~3s, Phase 3 随机 1-3s)
  5. 结束时 => SFX-09 连接成功音
行为:
  - 调用 .play('modem') 时触发
  - 可通过 options.speed 控制速率 (1.0 = 正常, 1.5 = 快速)
  - 可中断 (浏览器跳转完成时自动结束)
```

#### SFX-10: Glitch 爆发

```
输入: options { intensity: 0.3-1.0 }
算法:
  1. AudioBufferSourceNode — 白噪声, 增益 -10dB
  2. BiquadFilterNode — 带通, 中心频率随机 800-3000Hz
  3. WaveShaperNode — 模拟位压缩 (失真曲线)
  4. GainNode — 振幅包络: attack 20ms → hold 100-500ms → release 50ms
  5. OscillatorNode (LFO) — 调制滤波器频率 (20-50Hz 随机)
行为:
  - intensity 控制: 音量、带宽、时长、失真程度
  - 每次触发使用随机种子 (频率/时长/包络均不同)
  - 高 intensity 时加入 pan 随机偏移 (左/右声道抖动)
```

#### SFX-12: 镜中人低频

```
输入: 无 (持续播放, 在对话阶段)
算法:
  1. OscillatorNode #1 — 正弦波 25Hz (增益 -20dB, 几乎不可闻)
  2. OscillatorNode #2 — 正弦波 50Hz (增益 -24dB, 相位偏移)
  3. LFO — 0.1-0.3Hz 缓慢调制两个振荡器的增益
  4. BiquadFilterNode — 低通 100Hz (sub-bass only)
  5. 可选: 极轻微失真 (warm tube saturation 模拟)
行为:
  - 播放期间小幅降低 CRT 底噪增益 (避免低频叠加)
  - 对话进入第 3 轮后, 加入 0.5-2Hz 的振幅脉冲 (模拟心跳)
```

#### SFX-15~18: 结局音效

每个结局音效是上述音效的组合 + 独特处理:

| 结局 | 核心声 | 技术实现 |
|------|--------|----------|
| **A (断开)** | 连接断裂 + 音调骤降 + 真空 | → SFX-01 快速 fadeOut (1s) → 一声"咔"(噪声脉冲 + 低通) → 所有频率缓慢下降(2s) → 静默(2s) → 单声道 50Hz 极度微弱恢复(暗示"还在") |
| **B (接替)** | 持续低频 + 规律脉冲 | → SFX-01 fadeOut → 新低频循环(30Hz + 60Hz, 方波) → 每 2s 一个脉冲(短噪声) → 持续低振幅(监控设备的听感) |
| **C (穿越)** | Pan sweep + 混响膨胀 | → 对话最后一轮时 SFX-12 渐强 → 触发瞬间: 白噪声扫频 + pan 从左到右(3s) → 混响突然增大(convolver 模拟大空间) → 所有声音突然沉入 sub-bass → 静默 → 反向 pan 从右到左的微弱 SFX-01(从"里面"听) |
| **D (封印)** | 真空 + 遗忘 | → SFX-01 缓慢 fadeOut (3s) → 所有活跃振荡器逐个停止(间隔 0.5s) → 最终静默(5s) → SFX-01 以极低音量恢复正常(桌面保持安静) |

### 5.3 音频总线结构

```
AudioContext.destination
└── DynamicsCompressorNode (阈值 -12dB, 比例 3:1)
    └── MasterGain (主音量, 默认 0.7)
        ├── Bus: Ambient (SFX-01, 背景环境)
        │   └── BgGain (可动态调节)
        ├── Bus: UI (SFX-02~07, SFX-20)
        │   └── UIGain
        ├── Bus: Transition (SFX-08~09, 过渡音效)
        │   └── TransitionGain
        ├── Bus: Supernatural (SFX-10~14, 超自然音效)
        │   └── SupernaturalGain
        └── Bus: Ending (SFX-15~19, 结局音效)
            └── EndingGain
```

**动态混音规则**:
- 对话期间: `SupernaturalGain` +6dB, `UIGain` -3dB
- 结局触发时: 所有 Bus 在 1s 内 fadeOut, `EndingGain` +0dB
- 结局播放后: `Ambient` 以修改后的参数恢复

## 6. 音频架构设计

### 6.1 与现有代码的集成方案

音效引擎将作为全局对象 `AudioEngine` 独立封装，以最小侵入方式集成到现有代码：

```
arg-index.js 新增内容:
  [行 0-5]     AudioEngine 对象定义 (约 100-150 行)
  [初始化部分]  在 init() 中调用 AudioEngine.init()
  [关键钩子点]  在以下位置插入 AudioEngine.play() 调用:
                - openWindow() → SFX-02
                - closeWindow() → SFX-03
                - 所有 onclick 处理 → SFX-05
                - enterForum() → SFX-01(进入论坛变调)
                - enterWayback() → SFX-08
                - enterTerminal() → SFX-01(终端变调)
                - terminalKeydown() → SFX-07
                - connect 成功 → SFX-09
                - mirror dialogue 开始 → SFX-12
                - triggerEnding() → SFX-15~18
                - 全局 glitch 事件 → SFX-10
```

**集成原则**:
1. **零修改现有逻辑** — 只在入口/出口处追加 `AudioEngine.play()`，不改动现有函数内部结构
2. **AudioEngine 自行管理生命周期** — 创建节点、连接总线、资源回收均在引擎内部
3. **优雅降级** — 如果 AudioContext 创建失败（极旧浏览器），所有 `play()` 调用静默返回，不影响游戏运行
4. **用户交互门** — 首次用户交互（双击桌面图标或点击按钮）时初始化 AudioContext，遵守浏览器 autoplay policy

### 6.2 事件驱动设计

音效触发采用"调用即忘" (fire-and-forget) 模式：

```javascript
// 使用示例:
AudioEngine.play('click');          // SFX-05
AudioEngine.play('windowOpen');      // SFX-02
AudioEngine.play('modem');          // SFX-08 (自动播放到结束)
AudioEngine.play('glitch', {        // SFX-10 带参数
  intensity: 0.7,
  duration: 1.5
});

// 持续音效:
AudioEngine.play('crtHum');         // SFX-01 开始
AudioEngine.setBgIntensity(2);      // 增强 CRT 底噪 (紧张状态)
AudioEngine.stop('crtHum');         // SFX-01 渐出停止
```

### 6.3 AudioContext 生命周期

```
页面加载
  └── AudioEngine 对象定义 (惰性, 不创建 AudioContext)
      └── 首次用户交互 (点击/按键)
          ├── AudioEngine.init() — 创建 AudioContext + 主总线 + 压缩器
          ├── 开始播放 SFX-01 (CRT 底噪, 极低音量淡入 3s)
          └── [此后随时可以触发音效]
              └── 页面卸载 — AudioContext 自动销毁
```

## 7. 性能与体积评估

### 7.1 代码体积增量

| 项目 | 大小 | 备注 |
|------|:----:|------|
| AudioEngine 封装代码 | ~3-4 KB (约 100-150 行) | 全部合成逻辑 + 总线管理 |
| CRT 底噪消耗 | 6 个音频节点/端口 | 持续运行, CPU 占用 < 0.5% |
| 单次音效消耗 | 2-5 个节点, 播放后自动 GC | 短音效不累积 |
| Modem 拨号消耗 | 峰值 ~8 个节点 | 3-8s 后自动释放 |
| 内存占用 | < 1MB | 无任何音频文件加载 |

**对比**: 
- 方案 A (Web Audio API 合成): **+3-4KB JS, 0KB 音频资产, 零 HTTP 请求**
- 方案 B (Howler.js + 采样): +12KB (Howler.js) + 50-200KB (音频文件) + 3-5 个 HTTP 请求

### 7.2 性能预算

| 指标 | 预算 | 实际消耗 |
|------|:----:|:--------:|
| 同时发声数 | ≤ 8 | 峰值 ~6 (CRT 底噪 + 镜中人低频 + glitch → 可能同时 3-4 个活跃) |
| AudioContext 节点数 | ≤ 30 | 峰值 ~15 |
| CPU 占用 | < 2% | < 1% (现代浏览器) |
| 内存增量 | < 2MB | < 1MB |
| 加载延迟 | 0ms | 0ms (无网络加载) |

### 7.3 浏览器兼容性

| 浏览器 | 兼容性 | 说明 |
|--------|:------:|------|
| Chrome 90+ | ✅ | 完整支持 Web Audio API + auto-play policy |
| Firefox 90+ | ✅ | 同上 |
| Edge 90+ | ✅ | 同上 |
| Safari 15+ | ⚠️ | 需用户交互后 init AudioContext (已设计) |
| 手机浏览器 | ⚠️ | 非目标平台, 但 AudioContext 普遍支持 |

**注意**: Safari 的 AudioContext 有 known issue — 在 iframe 中可能被静音。本项目为非 iframe 部署, 无影响。

### 9.1 如果未来需要真实采样

```javascript
// 方案: 内联 base64 编码的极短音频片段
// 1. 在构建时 (手动) 将 1-3 秒 WAV 编码为 base64
// 2. 存储在 JS 文件的 Base64Audio 对象中
// 3. 用 AudioContext.decodeAudioData() 解码播放

const Base64Audio = {
  endingBPiano: 'data:audio/wav;base64,...',
  modemReal: 'data:audio/wav;base64,...'
};
```

**极限体积预算**: 每个音频片段 ~10-50KB base64 编码（1-3 秒 WAV）。仅用于必须真实采样的音效。

### 9.2 AudioEngine 接口预设

为方便其他团队成员调用, 预设简洁的触发接口:

```javascript
// 在 GAME_STATE 提交流程中预设 (不用改现有函数结构)

AudioEngine.play('windowOpen');

// 在论坛回复时:
AudioEngine.play('keyClick', { pitch: 'random' });
```
