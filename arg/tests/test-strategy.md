## 1. 测试目标

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| **P0** | 玩家能完整走通至少一个结局 | 5 条核心路径全部可抵达结局画面 |
| **P0** | 游戏不会因正常操作崩溃 | 连续 30 分钟操作无 JS 异常 |
| **P1** | 4 种结局互斥（一个游戏内只能触发一个） | 触发结局后所有路径被锁定 |
| **P1** | localStorage 跨会话持久化正常 | 刷新页面后 `endingEReady` 状态正确恢复 |
| **P2** | 边缘操作不会导致状态不一致 | 边界条件表中所有场景行为合理 |
| **P3** | Win98 视觉风格一致性 | 窗口、字体、颜色符合 2002 年 Win98 风格 |

## 2. 测试范围

### 2.1 纳入测试（In Scope）

| 系统 | 模块 | 测试重点 |
|------|------|----------|
| SYS-01 | 窗口管理系统 | 打开/关闭/最小化/最大化/拖拽/任务栏/开始菜单 |
| SYS-02 | 论坛浏览系统 | 警告页→论坛→时光机→快照 全流程 |
| SYS-03 | 终端交互系统 | 10 个命令全部可用 + 连接仪式感 |
| SYS-04 | 叙事推进系统 | 帖子渐进显示、关键路径触发、阶段转换 |
| SYS-05 | 镜中人对话系统 | 4 轮对话完整 + 对话中命令锁定 |
| SYS-06 | 结局触发系统 | 4 个结局全部可触发 + 互斥性验证 |
| | localStorage | 结局记录持久化 + 跨会话读取 |
| | UI/视觉 | Win98 风格一致性、结局 overlay 渲染 |

### 2.2 排除测试（Out of Scope）

| 项 | 排除理由 |
|----|----------|
| 广告系统（ad-system.js / ad-data.js） | 与游戏逻辑完全独立，不影响核心体验 |
| Google Analytics（gtag-config.js） | 外部分析服务，不影响游戏功能 |
| 移动端适配 | 目标平台为桌面端 1024×768+（GDD §5.4 W3 排除） |
| IE 浏览器兼容性 | 目标仅现代浏览器（Chrome/Edge/Firefox/Safari） |
| 无障碍访问（屏幕阅读器） | ARG 体验依赖视觉沉浸，非目标场景 |
| 性能压力测试（200+ 条命令） | 游戏体验 15-30 分钟，正常不会触发此边界 |
| 安全性测试（XSS 注入等） | 纯静态前端，无服务端，攻击面极小（代码审查已确认低风险） |

### 2.3 未实现功能不测试

以下功能在 GDD 中已设计但**尚未实现**，不纳入当前测试范围：

- 音效系统（S1） — Should Have
- Token-by-token 打字效果（S4） — Should Have
- Ending E 共存结局（C1） — Could Have，设计已定稿但代码未实现
- Tier 2/3 扩展内容（隐藏帖子等）
- 桌面随机 glitch 事件

## 3. 测试环境

### 3.1 推荐浏览器

| 浏览器 | 优先级 | 备注 |
|--------|--------|------|
| Google Chrome (v90+) | **主要测试平台** | 开发者工具方便调试 localStorage |
| Microsoft Edge (v90+) | 二级测试 | Chromium 内核，行为与 Chrome 一致 |
| Mozilla Firefox (v90+) | 三级测试 | 不同渲染引擎，检查兼容性 |
| Safari (v15+) | 可选 | macOS 用户检查 |

### 3.2 屏幕分辨率

| 分辨率 | 优先级 | 备注 |
|--------|--------|------|
| **1440 × 900** | **主要** | 团队推荐分辨率 |
| **1920 × 1080** | 二级 | Full HD 常见分辨率 |
| 1024 × 768 | 三级 | Win98 最小分辨率 |

### 3.3 测试工具

| 工具 | 用途 |
|------|------|
| Chrome DevTools (F12) | 查看 Console 错误、调试 GAME_STATE |
| Application → Local Storage | 查看/修改 `mirror_completed_endings` |
| Network 面板 | 确认无意外网络请求 |
| Console 面板 | 手动设置 `GAME_STATE` 辅助测试 |

### 3.4 测试辅助代码（Console 中运行）

```javascript
// 查看当前游戏状态
console.table(GAME_STATE);

// 手动解锁 Ending E 测试条件
localStorage.setItem('mirror_completed_endings', JSON.stringify(['A', 'B', 'C', 'D']));

// 查看已完成的结局
JSON.parse(localStorage.getItem('mirror_completed_endings') || '[]');

// 清除结局记录（重置 E 解锁条件）
localStorage.removeItem('mirror_completed_endings');

// 强制触发结局（跳过前置条件）
// 注意：仅用于渲染验证，不要用于流程测试
triggerEnding('A');
```

## 4. 测试类型

### 4.1 功能测试（Functional Testing）

**覆盖范围**: 所有 GDD 验收标准中标记为 ✅ 已实现的功能

**测试方法**: 手动逐条验证

**优先级**:
1. **核心路径测试** — 验证 5 条主路径可走通（每个结局一条）
2. **命令可用性测试** — 验证终端 10 个命令在正确条件下均有正确输出
3. **界面渲染测试** — 验证 5 个浏览器阶段 + 终端阶段 UI 正确

### 4.2 回归测试（Regression Testing）

**触发条件**: 代码修改后

**回归范围**:
- 烟雾测试清单（smoke-test-checklist.md）全部项目
- 受修改影响的子系统所有验收标准
- 所有 4 个结局路径快速走通

### 4.3 边界测试（Boundary Testing）

**覆盖场景**: 见 playtest-plan.md §7 边界条件表

**测试方法**: 故意使用异常操作序列，观察系统行为

### 4.4 体验测试（Experience Testing）

**测试方法**: 新人玩家首次体验 + 结构化记录

**评估维度**:
| 维度 | 评估方式 |
|------|----------|
| 情感弧线 | "好奇→不安→恐惧→共情→选择" 是否自然过渡 |
| 流程引导 | 玩家是否知道下一步该做什么 |
| 沉浸感 | Win98 外壳是否被意外打破 |
| 操作清晰度 | 终端命令是否易于理解和发现 |
| 完成感 | 结局后玩家是否感到满足 / 有重玩动力 |

## 5. Bug 分级标准

### P0 — Blocker（阻塞）

**定义**: 游戏无法正常运行，核心路径中断，或数据丢失

| 示例 | 描述 |
|------|------|
| 浏览器白屏 / JS 崩溃 | 页面无法加载 |
| 核心路径无法走通 | 某结局无法触发 |
| localStorage 数据损坏 | 已完成的结局记录丢失 |
| 结局触发后仍然能输入命令 | 互斥性失效 |

**处理**: 立即修复，不可发布

### P1 — Critical（严重）

**定义**: 功能不完整，体验严重受损，但核心路径存在

| 示例 | 描述 |
|------|------|
| 命令输出错误 | 某命令返回错误文本 |
| 视觉错位严重 | 窗口布局崩溃，文本溢出 |
| 状态不一致 | 论坛已推进但终端不知晓 |
| 帖子渐进显示逻辑错误 | 回复后帖子数未正确 +3 |

**处理**: 修复后方可发布

### P2 — Major（主要）

**定义**: 功能可用但不完善，体验受损但可接受

| 示例 | 描述 |
|------|------|
| UI 细节缺失 | Win98 风格不准确（字体、间距、颜色） |
| 动画/过渡卡顿 | 连接动画闪烁 |
| 边缘操作行为异常 | 特定非常规操作序列出现意外行为 |
| 文字错误 | 错别字、排版不整齐 |

**处理**: 修复或确认已知后发布

### P3 — Minor（次要）

**定义**: 建议改进，非功能性缺陷

| 示例 | 描述 |
|------|------|
| 视觉一致性建议 | 颜色微调、对齐优化 |
| 文案建议 | 措辞优化，增强沉浸感 |
| 体验优化建议 | 增加提示、改善引导 |
| 技术债务 | 可维护性改进建议 |

**处理**: 记录，按计划迭代

## 6. 测试数据管理

### 6.1 localStorage 数据

| 键名 | 用途 | 测试注意事项 |
|------|------|-------------|
| `mirror_completed_endings` | 记录已完成结局（数组 JSON） | 每次手动测试前清除，避免污染 |

**测试前清理**: 每轮测试开始前，打开 DevTools → Application → Local Storage → 右键 Clear All

### 6.2 测试账本

每次测试应记录：
- 测试日期 + 浏览器版本
- 测试路径（哪个结局 / 哪种边界场景）
- 测试结果（PASS / FAIL + Bug ID）
- 测试者签名（可选）

## 8. 附录：已知风险清单

### P0 风险（阻塞级）

| ID | 风险 | 场景 | 影响 | 缓解措施 |
|----|------|------|------|----------|
| R-P0-01 | 论坛自动推进 + 手动回复冲突 | 论坛帖子由 `postsRevealed` 控制渐进显示，每次回复 +3。如果玩家快速连续回复，可能跳过关键帖子内容 | 玩家错过叙事信息 | 建议回复后自动滚动到新帖子；关键帖子（#7 老刀部署监控脚本、#10 深海宣布关闭论坛）添加阅读状态标记 |
| R-P0-02 | 结局触发后浏览器窗口仍可操作 | `triggerEnding()` 锁定终端和输入，但未关闭浏览器窗口 | 玩家在结局覆盖画面下仍可操作浏览器，破坏沉浸感 | GDD §8.1 已识别此风险（P0），建议结局触发后自动最小化浏览器 |
| R-P0-03 | `seal` → 其他命令 → `confirm` 误触发 | 在 `seal` 后输入了其他命令再输入 `confirm`（非当前 `seal` 上下文），根据 GDD §5 结束系统边缘情况仍会触发结局 D | 玩家意外触发不该触发的结局 | GDD 已建议添加 `sealPending` 状态，当前代码（GAME_STATE schema v1.1）已新增此字段 |
| R-P0-04 | 快速双击/连击导致重复触发 | 玩家快速双击"继续"、回复按钮或结局命令 | 状态不一致或重复渲染 | 按钮应添加防抖（debounce）或点击后立即 disabled |

### P1 风险（严重级）

| ID | 风险 | 场景 | 影响 | 缓解措施 |
|----|------|------|------|----------|
| R-P1-01 | 终端内容全量重建性能下降 | `renderTerminal()` 每次命令后重建全部 HTML，`commandHistory` 增长时重建字符串变长 | 极端情况下可感知延迟（以当前规模风险低） | >50 条命令时切换增量追加模式 |
| R-P1-02 | 论坛 textarea 内容丢失 | `renderForumPage()` 重建论坛页面，若 textarea 有内容而触发重新渲染则内容丢失 | 玩家输入丢失 | 渲染前保存 textarea 值 |
| R-P1-03 | 连接时间硬编码 | 连接欢迎信息中"已运行 24 年 7 个月 18 天"硬编码，非动态计算 | 日期不随当前日期更新 | 改为根据 2002-11-15 动态计算 |
| R-P1-04 | `minWindow()` / `closeWindow()` 视觉混滑 | 两者均执行 `display:none`，玩家无法区分最小化和关闭 | Win98 沉浸感受损 | 最小化时添加视觉标记 |

### P2 风险（主要级）

| ID | 风险 | 场景 | 影响 | 缓解措施 |
|----|------|------|------|----------|
| R-P2-01 | 浏览器后退/前进/转到按钮无功能 | `browserBack()` / `browserFwd()` / `browserGo()` 是空函数 | 按钮始终 disabled，但可能让玩家困惑 | 实现简单浏览历史栈或移除无功能按钮 |
| R-P2-02 | `maxWindow()` 无法还原 | 最大化窗口后没有还原按钮 | 无法恢复原始尺寸 | 保存原始尺寸，第二次点击还原 |
| R-P2-03 | 隐藏帖子灰色样式与 disabled 元素混滑 | 隐藏帖子使用灰色文字+可点击样式 | 玩家可能误认为是不可点击元素 | 确保 hover 态视觉反馈清晰 |
